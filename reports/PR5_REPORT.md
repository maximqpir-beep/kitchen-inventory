## 3. Доработка индивидуального проекта

Создан Django-проект kitchen_site. Подключены приложения homepage (обзор), items (каталог и карточка предмета), movements (журнал и карточка перемещения). Предметная область сохранена: предмет связан с категорией, состоянием и помещением; перемещение связано с предметом и двумя помещениями.

Использована объектная модель предыдущей практики: Item, Category, Condition, Room, Movement. Данные загружаются из data/inventory.json через storage.py. Консольная программа main.py продолжает работать. Отдельные данные для сайта не создаются.

URL приложений подключены к корневому маршрутизатору через include. Динамические ID описаны int-конвертером. Используются имена маршрутов, пространства имен и reverse. View-функции обрабатывают запрос, получают предметные данные и возвращают HttpResponse.

## 4. Страницы и оформление

Созданы пять основных страниц, связанные общей навигацией. В каталоге реализован поиск по части названия без учета регистра. Карточка предмета содержит название, категорию, состояние, помещение, количество, цену и стоимость партии. Журнал показывает даты, маршруты и статусы перемещений.

| URL | Назначение |
|---|---|
| / | Обзор и статистика инвентаря |
| /items/ и /items/<id>/ | Каталог и карточка предмета |
| /movements/ и /movements/<id>/ | Журнал и карточка перемещения |

В версии ПР5 HTML формируется через общий каркас page() и format_html с экранированием текста. Подключены локальный Bootstrap и собственный CSS; оформление не требует CDN. На сайте доступны просмотр и поиск, изменение инвентаря остается в консоли.

Неизвестный адрес или ID возвращает 404. При недоступном или поврежденном JSON возвращается 503 без перезаписи исходника. GET и HEAD не изменяют данные; POST для этих страниц возвращает 405.
