# Защита ПР5

Группа ЭФБО-12-24. Система учета кухонного инвентаря.

## Что показать
1. Запуск по README и главную страницу.
2. Каталог, поиск «нож», карточку ножа и ссылку назад.
3. Журнал, выполненную и отмененную запись, ссылку на предмет.
4. Пустой результат поиска и страницу /items/999/.
5. Собственную 404 в режиме settings_demo по инструкции README.
6. Структуру проекта, чтение JSON и сохраненные классы ПР3.
7. Результаты manage.py check, pytest и flake8.

## Контрольные вопросы

1. **Веб-приложение.** Программа, с которой пользователь взаимодействует через браузер: отправляет запросы и получает страницы или данные.

2. **Фреймворк.** Основа приложения с готовыми механизмами и правилами организации кода.

3. **Django.** Веб-фреймворк Python. В проекте обеспечивает маршрутизацию, HTTP-ответы и обслуживание веб-приложений.

4. **Фреймворк и библиотека.** Библиотеку вызывает наш код; фреймворк организует выполнение приложения и вызывает наш код в нужные моменты.

5. **Django-проект.** Общие настройки и конфигурация сайта. Здесь это пакет kitchen_site.

6. **Django-приложение.** Модуль функциональности внутри проекта. Здесь homepage, items и movements.

7. **Проект и приложение.** Проект объединяет настройки и несколько приложений; приложение отвечает за отдельный раздел.

8. **manage.py.** Командная точка входа: запуск сервера, проверка настроек и другие команды Django.

9. **settings.py.** Хранит настройки приложений, middleware, языка, шаблонов, static и пути к JSON.

10. **urls.py.** Сопоставляет адреса с представлениями. Корневой файл подключает маршруты приложений через include.

11. **views.py.** Содержит функции обработки запроса: чтение объектов, подготовка результата и возврат HTTP-ответа.

12. **Development-сервер.** Локальный сервер для разработки, запускается manage.py runserver. Не предназначен для публичной промышленной эксплуатации.

13. **HTTP.** Протокол обмена запросами и ответами между клиентом и сервером.

14. **HTTP-запрос.** Сообщение клиента: что он хочет получить или сделать, по какому адресу и с какими данными.

15. **HTTP-ответ.** Результат обработки: код статуса, заголовки и обычно тело, например HTML.

16. **Части запроса.** В HTTP/1.1 это стартовая строка с методом, целью и версией, заголовки, пустая строка и необязательное тело. Представление на проводе зависит от версии HTTP.

17. **Части ответа.** В HTTP/1.1 — строка статуса, заголовки, пустая строка и тело, если оно предусмотрено. Например, 200 и HTML-документ.

18. **URL.** Адрес ресурса: схема, хост, необязательный порт, путь и параметры запроса; фрагмент после # обрабатывает браузер.

19. **Маршрут.** Правило сопоставления пути URL с обработчиком. Например, items/<int:item_id>/.

20. **Обработка URL Django.** Запрос поступает серверу, проходит middleware и URL resolver, затем вызывается view; сформированный ответ возвращается клиенту.

21. **HTTP-метод.** Обозначает действие над ресурсом. В проекте используются GET для просмотра и HEAD для получения заголовков без тела.

22. **GET и POST.** GET предназначен для получения данных и не должен изменять состояние. POST обычно передает данные для обработки или изменения. POST не делает данные автоматически защищенными: для транспорта нужен HTTPS.

23. **path().** Объявляет маршрут, view, дополнительные параметры и необязательное имя маршрута.

24. **Конвертер пути.** Проверяет и преобразует часть адреса в значение Python. Например, int принимает последовательность цифр и передает целое число.

25. **<int:id>.** Динамический сегмент с именем id. В проекте используется <int:item_id>; слово вместо цифр не сопоставится с маршрутом и даст 404.

26. **View-функция.** Функция, принимающая запрос и возвращающая ответ Django.

27. **Параметры view.** Первый параметр — HttpRequest; затем могут идти значения, полученные из маршрута, например item_id.

28. **Возвращаемое значение view.** HttpResponse или его подкласс. Исключение Http404 обрабатывается Django и превращается в ответ 404.

29. **HttpResponse.** Класс HTTP-ответа. В ПР5 ему передается HTML, созданный функцией page.

30. **Параметр URL во view.** path('<int:item_id>/', views.item_detail, name='detail') передает число в item_detail(request, item_id).

31. **Имена маршрутов.** Позволяют получать адрес через reverse('items:detail', args=[2]), не дублируя строковый путь по всему проекту.

32. **Разделение маршрутов и логики.** Адреса можно менять отдельно от правил учета. Предметные операции остаются в models и inventory.py.

33. **HTML.** Язык разметки структуры веб-документа: заголовки, ссылки, списки, таблицы и формы.

34. **Назначение HTML-документа.** Описывает содержимое страницы и его структуру для браузера и вспомогательных технологий.

35. **Части HTML-документа.** <!doctype html>, html, head с метаданными и body с видимым содержимым.

36. **HTML-элемент.** Часть документа, обычно заданная открывающим тегом, содержимым и закрывающим тегом; у некоторых элементов, например img, закрывающего тега нет.

37. **CSS.** Язык оформления: цвета, размеры, отступы, расположение и адаптивная верстка.

38. **CSS-селектор.** Определяет элементы, к которым применяется правило. .inventory-card выбирает элементы с соответствующим классом.

39. **Наследование стилей.** Некоторые свойства, например цвет и шрифт, передаются от родителя потомкам. Отступы и рамки обычно не наследуются автоматически.

40. **Bootstrap.** CSS-фреймворк с готовыми классами и компонентами; в проекте локально подключена версия 5.3.3.

41. **Назначение Bootstrap.** Готовые стили кнопок, форм, карточек и таблиц ускоряют верстку. Например, btn, form-control, table.

42. **Преимущества CSS-фреймворка.** Единообразие компонентов и базовая адаптивность. Собственный CSS задает оформление именно кухонного проекта.

43. **Предметная область.** Учет кухонного инвентаря: предмет, категория, состояние, помещение и перемещение.

44. **Реализованные страницы.** Обзор, список предметов, карточка предмета, история перемещений, карточка перемещения; дополнительно страницы ошибок.

45. **URL страниц.** /, /items/, /items/<id>/, /movements/, /movements/<id>/.

46. **View-функции проекта.** homepage.index, items.item_list, items.item_detail, movements.movement_list, movements.movement_detail; page_not_found и data_unavailable обрабатывают ошибки.

47. **Путь запроса к странице.** /items/2/ → kitchen_site.urls → items.urls → item_detail → JSON и объект Item → format_html/page → HttpResponse.

48. **Что сохранено из ПР3.** Консоль main.py, классы Item/Category/Condition/Room/Movement, inventory.py, storage.py, JSON и все прежние 42 теста.

49. **Почему пока без ORM.** ПР5 изучает HTTP, адреса и первые страницы. Перенос предметной модели в базу данных относится к следующему этапу.

50. **Изменения после базы данных.** Появятся Django-модели, миграции и ORM-запросы вместо JSON; затем формы, пользователи и права доступа.

51. **Источник данных сейчас.** data/inventory.json. storage.load_data создает объекты ПР3; страницы используют их атрибуты. В комплекте учебные данные, свои можно сохранить в том же формате.

52. **Дальнейшие возможности.** В ПР6 — шаблоны и static; затем ORM, база данных, веб-формы добавления и редактирования, авторизация и API.
