# Коротко для защиты ПР9, ПР10, ПР11

Тема: система учета кухонного инвентаря. Группа ЭФБО-12-24.

## ПР9 — модели и ORM

- `items/models.py`: категории, состояния, помещения, предметы; `movements/models.py`: перемещения.
- ForeignKey связывает предмет со справочниками, перемещение — с предметом и двумя помещениями.
- PROTECT запрещает удалить используемый справочник. related_name дает обратную связь `item.movements`.
- `makemigrations` создает описание изменений, `migrate` применяет его. Реальные изменения хранятся в `db.sqlite3`.
- `import_legacy` переносит данные из неизменного SQLite ПР7 одной транзакцией; при ошибке импорт откатывается.
- QuerySet ленивый: SQL выполняется при получении результата. filter отбирает, exclude исключает, Q объединяет условия.
- select_related получает ForeignKey одним JOIN; prefetch_related нужен для обратных и множественных связей.
- aggregate дает одну сводку; annotate добавляет показатель объекту/группе; F ссылается на столбец базы.
- Paginator получает только нужную страницу. Фильтры сохраняются в ссылках.
- Открой `/items/`, `/movements/`, `/statistics/`, `docs/ORM_QUERIES.md`.

## ПР10 — Admin и развитие ORM

- Admin — интерфейс управления моделями, доступный пользователям с нужными правами.
- ModelAdmin задает list_display, search_fields, list_filter, ordering, list_per_page.
- Inline показывает связанные записи внутри карточки. История readonly, изменения статуса идут через сервис.
- TextChoices задает PLANNED/COMPLETED/CANCELLED. В коде нет старого поля cancelled.
- Дата-миграция RunPython берет исторические модели через apps.get_model; сначала преобразует данные, затем удаляет поле.
- GeneratedField total_price рассчитывает quantity * unit_price в базе. Его нельзя вводить вручную.
- Slug — постоянный английский URL помещения. get_absolute_url возвращает маршрут карточки.
- Контекстный процессор передает название проекта и группу во все шаблоны.
- Debug Toolbar показывает 5 SQL-запросов каталога: один COUNT, один JOIN, три справочника; N+1 нет.
- Открой `/admin/`, карточку предмета с inline, карточку помещения, SQL-панель.

## ПР11 — формы

- Form проверяет произвольные данные (GET-фильтры); ModelForm связана с моделью и может сохранять ее.
- is_bound означает, что форме переданы данные; is_valid запускает проверку; cleaned_data содержит проверенные значения.
- clean_<field> проверяет одно поле, clean — сочетания полей. Модель дополнительно проверяет бизнес-правила.
- Поля формы перечислены явно: статус и исходное помещение пользователь прислать не может.
- В прошлое планировать нельзя, предмет должен быть исправен, помещения разные, второй план на ту же дату запрещен.
- При редактировании проверка исключает текущий объект, поэтому он не конфликтует сам с собой.
- Сохранение повторно проверяется в транзакции; UniqueConstraint защищает от двух активных планов на дату.
- POST → redirect → GET предотвращает повторное создание после обновления страницы результата.
- CSRF защищает изменяющие запросы. Авторизация и права дополнительно ограничивают запись.
- Отмена плана освобождает дату. Отмена выполненной последней записи откатывает помещение; история сохраняется.
- ImageField проверяет изображение; request.FILES содержит файл; multipart/form-data нужен для отправки.
- Открой `/movements/create/`, покажи прошлую дату и конфликт, отредактируй план, выполни/отмени его.

Скрипты SQL ПР7 и прежняя консоль сохранены для истории, сайт использует ORM.
Методички показывают Roomly; примеры бронирований адаптированы к планированию перемещений инвентаря.
