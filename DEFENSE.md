# Защита ПР6

Группа ЭФБО-12-24. Система учета кухонного инвентаря.

## Что показать
1. Запуск по README и главную страницу.
2. Каталог, поиск «нож», карточку ножа и ссылку назад.
3. Журнал, выполненную и отмененную запись, ссылку на предмет.
4. Пустой результат поиска и страницу /items/999/.
5. Собственную 404 в режиме settings_demo по инструкции README.
6. Структуру проекта, чтение JSON и сохраненные классы ПР3.
7. Результаты manage.py check, pytest и flake8.

## Где искать требования ПР6
| Требование | Пример в проекте |
|---|---|
| Общий каркас | templates/base.html |
| extends, block | items/templates/items/item_detail.html |
| include с аргументом | items/includes/item_card.html, подключение with item=item only |
| Контекст | items/views.py: ключи item, items, query |
| for / empty | items/item_list.html, movements/movement_list.html |
| if / elif / else | items/includes/state.html |
| name и app_name | items/urls.py; {% url 'items:detail' item.id %} |
| Фильтры | length, default, truncatechars, stringformat, date, money |
| CSS и изображения | homepage/static/homepage/css и img |
| JavaScript | homepage/static/homepage/js/catalog.js |
| Отказ от HTML в Python | Во views только render, контекст и объекты |

Покажи кнопку «Компактный вид»: она меняет CSS-класс сетки, текст кнопки и aria-pressed. Если реакции нет, проверь загрузку файла в Network и ошибки в Console браузера.

## Типовые ошибки для защиты
- Неверный ключ контекста или атрибут обычно дает пустую строку. Проверь совпадение имен в view и шаблоне.
- Отсутствующий файл шаблона дает TemplateDoesNotExist; незакрытый for/if — TemplateSyntaxError.
- Неверное имя маршрута или namespace в url дает NoReverseMatch.
- /items/abc/ не проходит int-конвертер; /items/999/ проходит маршрут, но объект не находится. Оба случая дают 404 на разных этапах.
- Значение с HTML-тегами экранируется; не добавляй safe к пользовательскому тексту без основания.
- Пустой список обрабатывается empty, отсутствующая категория в карточке — default.
- Пропавший CSS или SVG проверяется по адресу static, коду ответа и правильности пути.

## Контрольные вопросы

1. **Назначение шаблонов.** Описывают HTML отдельно от Python-кода. View передает данные, Django подставляет их в разметку.

2. **Неудобство HTML в Python.** Строки сложно читать, поддерживать и повторно использовать. Изменение оформления затрагивает код представлений.

3. **render().** Загружает шаблон, подставляет контекст и возвращает HttpResponse с полученным HTML и заданным статусом.

4. **Контекст.** Словарь имен и значений, доступных шаблону. Например, {'item': item, 'active': 'items'}.

5. **Передача списка.** Во view: render(request, 'items/item_list.html', {'items': items}); в шаблоне — цикл for item in items.

6. **{{ ... }}.** Вывод значения переменной, атрибута или результата фильтра. Текст по умолчанию экранируется.

7. **if и for.** if выбирает ветвь по условию; for перебирает коллекцию и повторяет фрагмент разметки.

8. **empty.** Ветка цикла for для пустой или отсутствующей коллекции. В каталоге выводит «Предметы не найдены».

9. **Базовый шаблон.** Общий каркас HTML: head, подключение ресурсов, навигация, main и footer. Здесь templates/base.html.

10. **extends и block.** extends указывает родительский шаблон; block задает участок, который дочерний шаблон может переопределить. Здесь title и content.

11. **include.** Вставляет отдельный шаблон в текущий. В проекте используются навигация, карточка предмета и бейджи статусов.

12. **Когда выделять фрагмент.** Когда разметка повторяется или образует самостоятельную часть, например карточку предмета. Правка одного include обновляет все места использования.

13. **name в path().** Дает маршруту устойчивое имя; адрес получается через reverse или тег url.

14. **app_name.** Задает пространство имен URL приложения. В items/urls.py app_name='items'.

15. **Пространства имен.** Различают одинаковые имена маршрутов разных приложений: items:detail и movements:detail.

16. **Литерал URL и тег url.** /rooms/ — жестко записанный путь из примера. {% url 'items:list' %} строит путь по текущей таблице маршрутов, поэтому изменение пути не требует править шаблон.

17. **Фильтры.** Преобразуют представление значения перед выводом. В проекте length, default, truncatechars, stringformat, date и собственный money.

18. **length.** Возвращает длину строки или коллекции. {{ items|length }} показывает число найденных партий.

19. **date.** Форматирует объект даты или времени. View преобразует ISO-строку created_at в datetime, а date:'d.m.Y H:i' задает вид.

20. **load static.** Подключает библиотеку тегов static. Сам тег static затем строит URL статического ресурса.

21. **Где хранятся ресурсы.** В static внутри приложения, с подкаталогом его имени: homepage/static/homepage/css/style.css. Это предотвращает конфликты имен.

22. **Подключение CSS.** {% load static %}, затем <link rel='stylesheet' href="{% static 'homepage/css/style.css' %}"> в base.html.

23. **Подключение изображения.** <img src="{% static 'homepage/img/kitchen.svg' %}" alt='Описание'>. Иллюстрация на главной и логотип включены в проект.

24. **Подключение JavaScript.** <script src="{% static 'homepage/js/catalog.js' %}" defer></script>. defer откладывает выполнение до разбора HTML.

25. **Собственный CSS и Bootstrap.** Bootstrap дает базовые компоненты, а style.css задает цвета, сетку, карточки, мобильную версию и характер проекта. Одно подключение Bootstrap не реализует индивидуальное оформление.

26. **View и шаблон.** View читает данные, ищет объект, проверяет его наличие и формирует контекст. Шаблон отвечает за HTML и условное отображение.

27. **Почему бизнес-логика вне шаблона.** Правила учета должны одинаково работать в консоли и веб-интерфейсе, быть проверяемыми и не зависеть от оформления. Методы Item остаются в models/.

28. **Почему JSON сохраняется.** ПР6 посвящена смене слоя отображения. Источник данных и объектная модель ПР3–ПР5 остаются прежними до практики по ORM.

29. **Архитектура ПР6 и ПР5.** ПР5: view → HTML-строки → HttpResponse. ПР6: view → context → template → HttpResponse. URL и JSON совместимы.

30. **Отказ от page().** Ее роль выполняет base.html. Старый homepage/html.py отсутствует; все страницы, включая 404 и 503, формируются через render().
