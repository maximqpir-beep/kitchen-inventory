# Подготовка к защите ПР7

## Что показать за 5 минут

1. Открой `sql/schema.sql`: пять таблиц, PK, FK и CHECK.
2. Покажи базу `data/inventory.sqlite`: 8 партий и 3 перемещения.
3. Открой `db/import_json.py`: проверка JSON, executemany, commit, rollback.
4. Открой `/items/?q=НОЖ`: WHERE и параметры; затем `/items/2/`: JOIN.
5. Открой `/items/available/?room=1`: только исправные предметы в цехе.
6. Открой `/movements/?date=2026-10-15&status=0`: дата и выполненные записи.
7. Открой `/statistics/?min_units=2`: COUNT/SUM, GROUP BY, HAVING.
8. Покажи `db/database.py`: sqlite3.Row и значения в `?`; views → context → шаблон.
9. Объясни: сайт читает SQLite; прежняя консоль работает с JSON. Для синхронизации нужен явный импорт, --replace полностью заменяет SQLite.

Пример запроса с параметром:

```python
conn.execute("SELECT name FROM items WHERE id = ?", (2,)).fetchone()
```

Неверный ID — 404, плохой параметр — 400, пустой результат — обычная страница,
недоступная база — 503. Это разные ситуации.

## Контрольные вопросы

### 1. Что такое база данных?

Организованное хранилище связанных данных; здесь это файл inventory.sqlite.

### 2. Чем база отличается от СУБД?

База — данные и структура, СУБД — программа управления ими. SQLite — СУБД.

### 3. Что такое реляционная база?

Данные представлены таблицами, связанными ключами.

### 4. Что такое таблица, запись и поле?

Таблица — набор однотипных данных, запись — строка, поле — столбец.

### 5. Какие типы есть в SQLite?

Классы хранения NULL, INTEGER, REAL, TEXT, BLOB. В проекте INTEGER и TEXT; отсутствие описания — NULL.

### 6. Зачем первичный ключ?

Однозначно определяет строку. id INTEGER PRIMARY KEY используется во всех пяти таблицах.

### 7. Зачем внешний ключ?

Связывает строки таблиц и запрещает ссылки на несуществующие записи, если включен foreign_keys.

### 8. Что такое SQL?

Язык определения структуры, чтения и изменения данных реляционной базы.

### 9. Чем SQL отличается от Python?

SQL описывает требуемые данные, Python организует выполнение запроса и обработку результата.

### 10. Для чего SELECT и FROM?

SELECT определяет возвращаемые столбцы или выражения, FROM — источник строк.

### 11. Для чего WHERE?

Отбирает отдельные строки до группировки, например только пригодный инвентарь.

### 12. Чем отличаются =, <> и !=?

= означает равно; <> и != в SQLite означают не равно.

### 13. Для чего IN, BETWEEN и LIKE?

IN проверяет набор значений, BETWEEN — включительный диапазон, LIKE — шаблон с % и _. В поиске каталога эти спецсимволы экранируются.

### 14. Как работают AND, OR, NOT?

AND требует выполнения обоих условий, OR — хотя бы одного, NOT отрицает условие; при смешивании полезны скобки.

### 15. Как проверить NULL?

Через IS NULL или IS NOT NULL, а не = NULL.

### 16. Для чего DISTINCT?

Убирает дубликаты выбранных сочетаний значений.

### 17. Для чего ORDER BY?

Задает порядок строк. Журнал сортируется по времени и ID, поэтому порядок устойчивый.

### 18. Чем отличаются ASC и DESC?

ASC — по возрастанию, DESC — по убыванию.

### 19. Для чего LIMIT и OFFSET?

LIMIT ограничивает число строк, OFFSET пропускает заданное число. В журнале по 20 записей.

### 20. Почему нужен ORDER BY при LIMIT?

Без сортировки состав страниц не гарантирован; дополнительный ID разрешает равенство времени.

### 21. Что такое агрегатная функция?

Вычисляет одно значение по набору строк: COUNT, SUM, MIN, MAX, AVG.

### 22. Чем COUNT(*) отличается от COUNT(column)?

COUNT(*) считает строки, COUNT(column) — только ненулевые значения столбца. При LEFT JOIN считаем i.id, чтобы пустая группа дала 0.

### 23. Для чего MIN, MAX, AVG, SUM?

Минимум, максимум, среднее и сумма. На странице статистики показаны цены и общая стоимость.

### 24. Для чего GROUP BY?

Объединяет строки в группы для агрегирования, например по помещению или категории.

### 25. Чем WHERE отличается от HAVING?

WHERE фильтрует исходные строки, HAVING — уже вычисленные группы, например SUM(quantity) >= ?.

### 26. В каком порядке обрабатываются части SELECT?

Логически FROM/JOIN, WHERE, GROUP BY, HAVING, SELECT, DISTINCT, ORDER BY, LIMIT/OFFSET.

### 27. Зачем sqlite3?

Это стандартный модуль Python для прямой работы с SQLite, без ORM.

### 28. Какие этапы работы с SQLite?

Открыть соединение, включить FK, выполнить SQL с параметрами, прочитать строки или commit, закрыть соединение.

### 29. Для чего cursor?

Выполняет запрос и позволяет получать его результат; conn.execute возвращает курсор.

### 30. Для чего commit?

Подтверждает изменения текущей транзакции; rollback отменяет их при ошибке.

### 31. Почему нельзя подставлять ввод через f-строки?

Это позволяет изменить смысл запроса — SQL-инъекция. Параметры передаются отдельно.

### 32. Что такое параметризованный запрос?

SQL содержит ?; значения передаются вторым аргументом execute, например execute(sql, (item_id,)).

### 33. Зачем executemany?

Выполняет один запрос для нескольких наборов параметров; используется при импорте справочников, предметов и перемещений.

### 34. Чем файловая база отличается от :memory:?

Файл сохраняется между запусками; база :memory: живет только в соответствующем соединении.

### 35. Когда полезна :memory:?

Для небольших временных вычислений и изолированных тестов, если не нужны общие соединения.

### 36. Как получить SELECT в Python?

Через fetchone, fetchall или перебор курсора. row_factory = sqlite3.Row дает row["name"].

### 37. Какие операции были до базы?

Консоль создавала партии, меняла состояния, перемещала и отменяла перемещения, сохраняла JSON; сайт показывал данные.

### 38. Чем база удобнее JSON?

SQL фильтрует и группирует данные, FK проверяют связи, транзакции обеспечивают целостность изменений.

### 39. Какие таблицы и связи используются?

categories, conditions, rooms связаны с items; movements ссылается на items и дважды на rooms. См. sql/schema.sql.

### 40. Какие запросы нужны проекту?

Списки, поиск по имени и справочникам, исправный инвентарь, карточки с JOIN, журнал по дате/статусу, агрегаты и группировки. Все 16 используются сайтом.
