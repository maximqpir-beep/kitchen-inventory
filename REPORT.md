## 1. Цель работы
Создать начальный веб-интерфейс системы учета кухонного инвентаря на основе объектной модели ПР3. Освоить структуру Django-проекта, HTTP-запросы и ответы, маршрутизацию, view-функции и оформление страниц.

## 3. Доработка индивидуального проекта
Создан Django-проект kitchen_site и подключены три приложения: homepage - обзор, items - каталог инвентаря, movements - журнал перемещений. Используется Django 5.2. Сохранены main.py, классы предметной области, функции inventory.py и storage.py, JSON-хранилище и тесты ПР3.

Реализованы пять основных страниц: главная /; список предметов /items/; карточка /items/<id>/; список перемещений /movements/; карточка /movements/<id>/. Например, /items/2/ показывает нож, а /movements/1/ - его перемещение. В каталоге работает поиск по части названия без учета регистра.

Корневая маршрутизация через include подключает адреса приложений. Динамические сегменты используют int-конвертер. У маршрутов заданы name и app_name; ссылки формируются через reverse. View-функции читают JSON, получают объекты и возвращают HttpResponse. В этой версии HTML собирается в Python через format_html и общий каркас page(). Подставляемый текст экранируется.

## 4. Данные и оформление
Источник данных - data/inventory.json. В памяти используются объекты Item, Category, Condition, Room и Movement, а не отдельные копии данных для веб-интерфейса. Связи предмета с помещением и записи перемещения с предметом сохранены. В комплект включены восемь учебных партий и три записи перемещений, одна из которых отменена.

На главной выводится статистика. Карточка предмета содержит категорию, состояние, помещение, количество, цену, стоимость и результат проверки пригодности. Карточка перемещения показывает маршрут, дату, статус и ссылку на предмет. Все страницы связаны общей навигацией.

Подключены Bootstrap 5.3.3 и собственный CSS. Файлы находятся внутри проекта, поэтому оформление не зависит от CDN. Используются семантические HTML-элементы, карточки, таблица, форма поиска и адаптивная сетка. Данные через HTTP не изменяются; редактирование остается в консольном меню ПР3. ORM, формы изменения данных и регистрация на этом этапе не добавлялись.

## 5. Проверки и результат
manage.py check завершился без замечаний. Выполнены 64 теста pytest: сохраненные проверки ПР3 и проверки веб-страниц. Проверены пять маршрутов, имена URL, поиск, связанные объекты, состояния, пустые списки, экранирование текста, ответы 404/405/503 и отсутствие записи в JSON при GET. flake8 не обнаружил замечаний.

Встроенный сервер запущен; выполнены реальные HTTP-запросы к страницам и CSS. Собственная страница 404 проверена при DEBUG=False в settings_demo. При отсутствующем или поврежденном JSON возвращается 503, файл не перезаписывается. Автоматический браузер в среде подготовки не запустился; визуальную проверку перед защитой нужно выполнить на компьютере студента.

Объектная модель ПР3 получила веб-интерфейс на Django с маршрутизацией, пятью страницами и навигацией. Консольная версия сохранена, предметные данные остаются в JSON. Следующий этап - перенос HTML в систему шаблонов Django. Фиксация результата в личном репозитории выполняется студентом.
